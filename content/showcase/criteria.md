**Purpose.** Transparent criteria so review feels fair and rejections are useful. For submitters and for reviewers.

**Contains.**
- The four checks: it runs, it is documented, it is honest, it is yours
- What "it runs" means for a library, a service, and a hardware build
- Documentation floor: a README that gets a stranger to first output
- Honesty rule: no claimed capability that the artifact does not have
- Attribution and licence requirements for derived work
- Common rejection reasons with a fix for each
- Appeal path if you think a reviewer got it wrong

**Primary CTA.** Check your build against the four checks before submitting.
